# hydra 起動キーの棚卸し (2026-09-04)

## 一覧

現在定義されている hydra は 5 つ。すべてキーに割り当て済み。

| hydra | 起動キー | スコープ | 定義 / 束縛 |
|---|---|---|---|
| `hydra-zoom` | `<f2>` | **グローバル** | `my-appearance.el:151,158` |
| `hydra-diff-hl` | `C-c g` | **グローバル** | `my-vc.el:64,86` |
| `hydra-flymake` | `C-c ! h` | `flymake-mode-map` | `my-lsp.el:155,161` |
| `hydra-markdown` | `C-c .` | `markdown-mode-map` | `my-text.el:295,352` |
| `hydra-dired` | `.` | `dired-mode-map` | `my-dired.el:56,60` 付近 |

## 統一感の評価

キーの選び方には一貫した軸が 2 本あり、それ自体は整っている。

- グローバル 2 つは「どこでも使う操作」で、`<f2>`（ファンクションキー）と
  `C-c g`（git-gutter 時代からの継承）
- モードローカル 3 つは「そのモードの機能群の入口」で、`C-c ! h` は flycheck
  慣例の `C-c !` プレフィックス配下、`C-c .` は markdown 専用の空きキー

崩れているのは 1 点だけ。

`hydra-dired` の `.` は `C-c` プレフィックスを介さない裸のキーで、他の 4 つと
系統が違う。ただし dired は read-only バッファで単キーコマンドが標準
（`m` `d` `x` `g` …）なので、**dired の作法としてはこちらが正しく**、
他と揃えて `C-c .` にすると逆に浮く。

もう 1 つ、性格の違いが揃っていない。

| hydra | 抜け方 |
|---|---|
| `hydra-zoom` | 赤（残る）。`0` だけ抜ける |
| `hydra-dired` | ピンク（残る） |
| `hydra-flymake` | 残る。`q` / `l` / `L` で抜ける |
| `hydra-diff-hl` | 残る。明示的な抜けキー無し（`C-g` のみ） |
| `hydra-markdown` | **`:exit t`（1 回で抜ける）** |

`hydra-markdown` だけが青（ワンショット）で、他 4 つは繰り返し前提。挿入系
コマンドの集まりなので妥当な選択だが、「hydra を出したら連続操作できる」
という期待とは逆になる。`hydra-diff-hl` に `q` が無いのも他 3 つと不揃い。

## F2 をモード別にするかどうか

上の表を見ると、**F2 をモード別に分岐させると系統が 3 本目に増える**
（グローバル / モードローカルの `C-c` 系 / モードローカルのファンクションキー）。
既存 5 つのうちファンクションキーはグローバルの `hydra-zoom` だけなので、
`C-c .` のまま据え置くほうが今の構造には素直。

`C-c .` が覚えにくいのが不満なら、F2 を触るより **markdown 側を `C-c ! h` と
同系の階層に寄せる**（例: `C-c m` などモードの頭文字プレフィックス）ほうが、
系統を増やさずに済む。

なお `<f2>` は Org 方式だった頃（`docs/archive-init.org:325`）から
`hydra-zoom` 一本で、markdown の hydra が F2 に載っていたことは一度もない。
